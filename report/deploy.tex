\section{Deployment and Maintenance}
\label{sec:deploy}

The delivered deployment is a portable SQLite file backed by a reproducible
build rather than a manually edited database. SQLite is appropriate for the
course project because it requires no server process and keeps the schema,
indexes and data in one file \cite{sqlite}. The current database is
\texttt{schema/environment.db} and is approximately \mDbMiB{} MiB.

A clean deployment follows one order: retain or back up any current database,
build a staging database from the BCNF CSV files, verify it independently and
only then publish the resulting file. The builder refuses to overwrite an
unrelated database unless the operator explicitly requests replacement.

\begin{lstlisting}[language=bash,caption={Linux initialization and independent verification},
label={lst:deploy-linux}]
./setup_linux.sh
python3 -m schema.scripts.setup.verify_database \
  --database schema/environment.db
\end{lstlisting}

Windows uses \texttt{setup\_windows.bat} and the same Python modules. The
database itself is cross-platform; only the command wrapper differs.

\subsection{Backup and Restore}
\label{subsec:backup-restore}

Backup uses SQLite's consistent backup mechanism and verifies the produced
file. Restore validates the candidate backup before replacing a destination,
so a corrupt input cannot erase a working database.

\begin{lstlisting}[language=bash,caption={Checked backup and restoration workflow},
label={lst:backup-restore}]
python3 -m schema.scripts.maintenance.backup_database \
  --database schema/environment.db \
  --output schema/backups/environment.db
python3 -m schema.scripts.maintenance.restore_database \
  schema/backups/environment.db \
  --database schema/environment-restored.db
\end{lstlisting}

The competency test suite rebuilds the database in a temporary directory,
creates a backup, restores it and compares SHA-256 content checksums over every
table ordered by its primary key. This compares content independently of
SQLite's physical page layout.

\subsection{Maintenance Procedure}
\label{subsec:maint}

\begin{enumerate}[leftmargin=*]
  \item Preserve the new source file and update the source/exclusion register.
  \item Run extraction and review changes in the quality, conflict and
  quarantine files.
  \item Regenerate the normalization stages and confirm that row accounting
  balances.
  \item Review any required change to the approved ERD before modifying the schema.
  \item Create a verified backup of the current database.
  \item Build a new staging database and run the independent verifier and test
  suite.
  \item Re-run the competency benchmark and regenerate report measurements.
  \item Publish the updated database only after all verification checks pass.
\end{enumerate}

The current project uses SQLite as a local file-based deployment and does not
provide authenticated multi-user access. A future server migration would
need authentication, authorization, concurrency control and an operational
backup schedule, but it should retain the same keys, source-traceability rules and
competency questions.
