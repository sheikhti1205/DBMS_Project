\section{ETL Methodology}
\label{sec:etl}

Extract--Transform--Load (ETL) is the complete path from an approved source
block to a constrained SQLite row. It is not limited to the final insertion
command. The project preserves intermediate stages so a reviewer can locate
where a value is reshaped, reconciled, aggregated or rejected.

The principal integration difficulty is that most source files cannot be
merged row for row. They use different station labels, reporting periods and
observation grains and some lack identifiers required by the final model. The
pipeline therefore treats reconciliation as an explicit transformation rather
than assuming that similarly named columns represent the same fact.

The BMD temperature input is a project-formatted workbook made from the
retained PDF publication. The committed extraction code starts from that
workbook; the original conversion procedure was not recorded. A separate
comparison checks the first, middle and last station rows on all 18 workbook
sheets against the PDF: all 1,296 sampled monthly values agree. This is a
sample check, not an exhaustive verification of every cell. The comparison
script and file hashes are supplied with the normalization evidence.

\subsubsection{Extract}

The extraction program reads the \mSourceFiles{} approved structured files and
creates \mSourceBlocks{} named 0NF blocks. Source-specific readers handle
merged headings, station labels outside data rows, repeated day or month
columns and fiscal-year text. The original file is never overwritten. Each
output name retains the organisation, workbook and sheet identity.

\subsubsection{Transform}

Transformation converts repeated columns into explicit observations, parses
types and standardizes only documented variants. Asterisks, \texttt{ND},
\texttt{N/A}, spreadsheet errors and blank cells become \texttt{NULL} when
they mean unavailable data; a measured zero remains zero. Daily BRRI
maximum-temperature readings are reduced to the monthly maximum and
minimum-temperature readings to the monthly minimum. Daily rainfall is summed,
daily humidity is averaged and sunshine remains at day grain. The
transformation keeps the number of contributing days so sparse months remain
detectable.

The program resolves competing values through a documented meteorological
precedence: BMD, then BRRI, then BBS. Identical duplicates, rounding
differences and substantive disagreements are counted separately. An
implausible or structurally invalid row enters the quarantine register instead
of being corrected by guesswork.

These rules also explain why record totals change. Expanding repeated day and
month columns increases the 1NF count, while aggregation and conflict
resolution reduce later counts. Table~\ref{tab:etl-accounting} reports the
stages without presenting the change as unexplained data loss.

\subsubsection{Load and Verify}

Reference and time relations are loaded before dependent observations.
Headers must match the schema definition file and each field is converted to
its declared SQLite type. The builder writes to a staging database, enables
foreign keys and replaces the delivered file only after both SQLite checks
pass.

\begin{lstlisting}[language=Python,caption={Core guarded load used by the database builder},
label={lst:etl-load}]
with sqlite3.connect(staging) as db:
    db.execute("PRAGMA foreign_keys = ON")
    db.executescript(schema_sql)
    for table, rows in prepared_rows.items():
        db.executemany(insert_sql(table), rows)
    if db.execute("PRAGMA foreign_key_check").fetchall():
        raise RuntimeError("foreign-key violation")
    if db.execute("PRAGMA integrity_check").fetchone()[0] != "ok":
        raise RuntimeError("integrity failure")
    db.commit()
os.replace(staging, destination)
\end{lstlisting}

The project implementation additionally validates CSV headers, field counts,
data types, schema fingerprints and row counts. An independent verifier then
compares database objects, columns, keys, checks and relationships with
\texttt{schema/erd\_contract.json}.

\begin{table}[H]

\label{tab:etl-failures}
\begin{tabular}{L{0.24\textwidth}L{0.29\textwidth}L{0.37\textwidth}}
\toprule
Failure & Effect & Resolution \\
\midrule
Merged and repeating layouts & Generic row readers assign the wrong identity &
Use block-specific boundaries and make date and station values explicit. \\
Source grains do not match & Daily values cannot be inserted into a monthly
key unchanged & Aggregate by measurement semantics and record contributing
days. \\
Inconsistent entity names & Valid observations become orphan rows & Apply

Malformed values or dates & Type conversion or range checks fail & Use

Missing relationship parent & A foreign key blocks the load & Confirm the

Schema or header mismatch & Columns can enter the wrong target field & Stop before

Interrupted or failed build & A partial database could replace a good database &
Build in a staging file and replace the working database only after the new

The source-reader total is a separate extraction-accounting measure rather than
the first normalization-stage row count. The 1NF total counts atomic
observations after repeated spreadsheet structures are expanded, while later
stages also apply decomposition, aggregation and conflict resolution.

Row totals are not expected to decrease uniformly at every theoretical stage:
decomposition can create reference rows while aggregation can collapse many
daily readings into one month. The review files close these changes by relation
instead of treating the difference as unexplained data loss.
